## Key Question 1: Boot path — what runsc does between `runsc run`/`do` and the first app instruction, and which steps are essential vs. defense-in-depth

### Takeaway
The runsc launcher is a three-process Linux-specific pipeline (runsc → `boot` sentry process → `gofer` process) that relies on clone-with-namespaces, pivot_root into a tmpfs chroot, uid/gid maps, capabilities, memfd, cgroups, prctl and seccomp. Almost all of it is defense-in-depth that the in-tree test harness already bypasses (`--TESTONLY-unsafe-nonroot`, `--ignore-cgroups`, `--network=none`, `Config.DisableSeccomp`), and `runsc/boot/loader_test.go` demonstrates an in-process boot with an in-process gofer. The genuinely essential host primitives for `Loader.New` are: a platform, an mmap-able memory file (memfd today), host `clock_gettime`/TSC, epoll (via `pkg/fdnotifier`), and the ability to import stdio FDs.

### Inferences
- A macOS demo can skip every namespace/chroot/cgroup/seccomp/capability step by (a) adding a darwin build of `runsc/sandbox` that starts the sentry with a plain `exec.Cmd` (no `Cloneflags`, no `Credential`, no uid maps), (b) exposing `DisableSeccomp` as a flag or forcing it under `GOOS=darwin`, and (c) running with `--ignore-cgroups --network=none --TESTONLY-unsafe-nonroot`. This matches what `loader_test.go` already does in-process.
- The two unavoidable non-platform host dependencies in `Loader.New` are the memory file (memfd → needs `shm_open`/`mkstemp`+`ftruncate` on macOS, see Q4) and `pkg/fdnotifier` epoll (needs a kqueue port, see Q2).
- `sandboxexec` offers no shortcut: it is a thin OCI/runsc client.

### Gaps
- Did not trace `runsc/container/container.go` chroot/ `Create` steps beyond the gofer/erofs code; the gofer spawn (`createGoferProcess`) uses the same `donation`/namespace machinery as the sandbox and is Linux-only, but line-level detail was not collected.
- No in-tree flag disables the IPC/mount/UTS/PID namespace list at sandbox.go:1333-1338; a port needs code, not just flags.

## Key Question 2: Filesystem — how the sentry reaches host files (lisafs/gofer, directfs, host FD import, erofs) and what macOS lacks

### Takeaway
Every host-file path in gVisor is built on Linux-only syscalls (`openat2`, `statx`, `getdents64`, `renameat2`, `fallocate`, `*xattr`, `O_PATH`, `AT_EMPTY_PATH`, `mknodat`, `eventfd2`, `epoll`). The transport (`pkg/unet`/`pkg/lisafs` over AF_UNIX with `SCM_RIGHTS`) is portable, but `pkg/lisafs` drags in `pkg/flipcall` (futex) and `pkg/fdchannel`. The least-Linux-dependent rootfs is **EROFS**: runsc already has a "goferless" mode where it `os.Open`s the image and the sentry `mmap`s it read-only — the only host primitives are `open`, `fstatfs` and `mmap`, all available on macOS. A tmpfs root or EROFS root plus host-FD stdio is the right demo path; `pkg/fdnotifier` (epoll) remains a blocking dependency because `fsimpl/host` and the VFS import graph require it.

### Cited Findings

**lisafs + gofer process [PARITY]**
- `pkg/lisafs` is 8043 LOC; its transport is `pkg/unet`: `socket(AF_UNIX, SOCK_SEQPACKET|SOCK_STREAM, SOCK_CLOEXEC)` and `socketpair` ([pkg/unet/unet.go:43-51](pkg/unet/unet.go), [:193](pkg/unet/unet.go)) with FD passing via `unix.UnixRights`/`ParseUnixRights` ([pkg/unet/unet.go:265](pkg/unet/unet.go), [:295](pkg/unet/unet.go)) — portable. `pkg/urpc` documents that FDs ride on SCM_RIGHTS ([pkg/urpc/urpc.go:67](pkg/urpc/urpc.go)).
- `pkg/lisafs` imports `pkg/flipcall` and `pkg/fdchannel` (scratch `go list` closure). On darwin `pkg/flipcall` fails to compile because `ctrl_futex.go` references `futexSetPeerActive/futexWakePeer/futexWaitUntilActive` that exist only in a linux file ([pkg/flipcall/ctrl_futex.go:60-66](pkg/flipcall/ctrl_futex.go)); `pkg/fdchannel` fails on `unix.SOCK_CLOEXEC` ([pkg/fdchannel/fdchannel_unsafe.go:36](pkg/fdchannel/fdchannel_unsafe.go)) even though its build tag already lists darwin ([:15](pkg/fdchannel/fdchannel_unsafe.go)).
- The gofer server implementation lives at `runsc/gofer/fs` (not `runsc/fsgofer`; 1784 LOC in `lisafs.go`, plus a 38-LOC seccomp filter in `runsc/gofer/fs/filter/filter.go`). Its host calls include `Openat2`+`RESOLVE_NO_SYMLINKS`, `Statx` with `STATX_*` masks, `O_PATH`, `AT_EMPTY_PATH`, `Mknodat`, `Fallocate`, `Fsetxattr/Fgetxattr/Flistxattr/Fremovexattr`, `Lsetxattr/Lgetxattr/Llistxattr/Lremovexattr`, `Getdents`, `Linkat`, `Fchownat`, `Fchmodat`, `Fstatfs`, `Setgroups`, `Gettid`, raw `SYS_SETREUID/SYS_SETREGID` (per-thread credential switching), `Accept4`, `SOCK_SEQPACKET` (grep of `unix.*` identifiers across `runsc/gofer/fs/*.go`; 89 lines match Linux-only identifiers). The gofer entry (`runsc/cmd/gofer.go`, 684 LOC) `chroot`s ([runsc/cmd/gofer.go:361](runsc/cmd/gofer.go)), installs seccomp ([:408](runsc/cmd/gofer.go)) and unmounts `/proc` ([:333](runsc/cmd/gofer.go)); all skippable under `TestOnlyAllowRunAsCurrentUserWithoutChroot` ([:284](runsc/cmd/gofer.go), [:312](runsc/cmd/gofer.go)).
- Shared helpers `pkg/fsutil` use `unix.Getdents`, `SYS_UTIMENSAT`, `SYS_RENAMEAT2`, `SYS_NEWFSTATAT` ([pkg/fsutil/fsutil.go:35](pkg/fsutil/fsutil.go), [pkg/fsutil/fsutil_unsafe.go:45-78](pkg/fsutil/fsutil_unsafe.go)); on darwin: `undefined: unix.Getdents, unix.SYS_UTIMENSAT, unix.SYS_RENAMEAT2`. `pkg/fsutil` is in the dependency closure of `pkg/sentry/kernel` and `tmpfs`.

**directfs (default on) [PARITY]**
- `--directfs` defaults to true ([runsc/config/flags.go:169](runsc/config/flags.go)). `pkg/sentry/fsimpl/gofer/directfs_inode.go` (1027 LOC) performs host calls directly from the sentry: `Statx` (×4, with `STATX_BASIC_STATS|STATX_BTIME`), `Openat`+`O_PATH`/`O_NOFOLLOW`/`O_DIRECTORY`, `AT_EMPTY_PATH` (×4), `AT_NO_AUTOMOUNT`, `Mknodat`, `Mkdirat`, `Linkat`, `Symlinkat`, `Readlinkat`, `Unlinkat(AT_REMOVEDIR)`, `Fsetxattr/Fgetxattr/Flistxattr/Fremovexattr`, `Fchownat`, `Fchmod`, `Ftruncate`, `Fstatfs`, `UTIME_OMIT` (identifier census). `gofer.go` also uses `Statx(AT_EMPTY_PATH, STATX_SIZE)` ([pkg/sentry/fsimpl/gofer/gofer.go:1438](pkg/sentry/fsimpl/gofer/gofer.go)) and `Dup3(O_CLOEXEC)` ([:2370](pkg/sentry/fsimpl/gofer/gofer.go)). macOS has none of `statx`, `O_PATH`, `AT_EMPTY_PATH`, `mknodat` semantics for sockets via `O_PATH`, or `f*xattr` (it has `fgetxattr` with a different signature/options arg).

**Host FD import (stdio) [DEMO]**
- `pkg/sentry/fsimpl/host` (1879 LOC) backs imported FDs. It uses `ioctl(TCGETS)` to detect TTYs ([pkg/sentry/fsimpl/host/ioctl_unsafe.go:24-35](pkg/sentry/fsimpl/host/ioctl_unsafe.go)) (macOS uses `TIOCGETA` and a different `termios` layout), `FIONREAD` ([host_unsafe.go:24](pkg/sentry/fsimpl/host/host_unsafe.go)), `Statx`, `SYS_EVENTFD2`, `Fallocate`, `SYS_UTIMENSAT`, `Fsync/Fdatasync`, `SetNonblock`, `fcntl(F_GETFL)` (identifier census). - `pkg/fdnotifier` (409 LOC, every file tagged `linux`) is the sentry's host readiness notifier: `EpollCreate1` ([pkg/fdnotifier/fdnotifier.go:102](pkg/fdnotifier/fdnotifier.go)), `EpollCtl ADD/DEL/MOD` with `EPOLLET` ([:71-85](pkg/fdnotifier/fdnotifier.go)), raw `SYS_EPOLL_PWAIT` ([pkg/fdnotifier/poll_unsafe.go:77](pkg/fdnotifier/poll_unsafe.go)). - `pkg/sentry/hostfd` (`hostfd.go`, `hostfd_linux.go`, `hostfd_unsafe.go`) uses raw `SYS_PREAD64/SYS_PWRITE64/SYS_PREADV2/SYS_PWRITEV2` ([pkg/sentry/hostfd/hostfd.go:104-146](pkg/sentry/hostfd/hostfd.go)) and a linux-only `MaxReadWriteIov`; on darwin: `undefined: unix.SYS_PREAD64 ... - `pkg/rawfile` (3 linux-tagged files, functions `BlockingPoll`, `NonBlockingWrite(Iovec)`, `NonBlockingSendMMsg`, `BlockingRead`, `BlockingReadvUntilStopped`, `BlockingRecvMMsgUntilStopped`, `BlockingPollUntilStopped`, `GetMTU`) is imported by `pkg/eventfd` ([pkg/eventfd/eventfd.go:126](pkg/eventfd/eventfd.go)), which `pkg/unet` imports, which `pkg/eventchannel`/`pkg/metric`/`pkg/lisafs` import — so it also blocks loading of every sentry package on darwin (scratch build errors for `kernel`, `vfs`, `tmpfs`, `mm`, `loader`, `pgalloc`, `erofs`, `netstack`, `time`, `lisafs`, `runsc/cmd`, `runsc`). **[DEMO]** (stubbable; `recvmmsg`/`sendmmsg` have no macOS equivalent, `poll`/`readv` do).

**EROFS rootfs — the goferless path [DEMO candidate]**
- `pkg/erofs` + `pkg/sentry/fsimpl/erofs` total 3520 LOC. The image is read via `unix.Mmap(fd, 0, size, PROT_READ, MAP_SHARED)` ([pkg/erofs/erofs.go:254-269](pkg/erofs/erofs.go)) and `unix.Fstatfs(imageFD)` ([pkg/sentry/fsimpl/erofs/erofs.go:236](pkg/sentry/fsimpl/erofs/erofs.go)). Mount data is `ifd=<fd>` ([runsc/boot/vfs.go:622-634](runsc/boot/vfs.go), [:1145-1150](runsc/boot/vfs.go)); `GoferMountConf` lower types are `none|lisafs|erofs` ([runsc/specutils/gofer_conf.go:95-120](runsc/specutils/gofer_conf.go)).
- `shouldSpawnGofer` returns false when no mount uses lisafs and no device gofer is needed ([runsc/container/container.go:1628-1637](runsc/container/container.go)); in that case runsc itself `os.Open`s the rootfs image and any EROFS submount images and passes the FDs to the sentry — the code panics "goferless mode is only possible with EROFS rootfs" otherwise ([runsc/container/container.go:1748-1779](runsc/container/container.go)). With a gofer, the EROFS FD is still just `os.Open(rootfsHint.Mount.Source)` ([:1902-1907](runsc/container/container.go)).
- EROFS on darwin still cannot load because of its closure: `pkg/aio`, `pkg/sentry/hostfd`, `pkg/sentry/usage`, `pkg/rawfile`, `pkg/fdnotifier`, `pkg/eventfd`, `pkg/memutil`, `pkg/sighandling`, `pkg/sentry/hostmm`, `pkg/unet`, `pkg/sentry/pgalloc`, `pkg/cpuid` (scratch `go list -deps`).

**Other registered filesystems**
- `runsc/boot/vfs.go` registers 13 types: `cgroupfs, cgroup2fs, devpts, dev, devtmpfs, erofs, fuse, gofer, overlay, proc, sys, tmpfs, mqfs` ([runsc/boot/vfs.go:117-126](runsc/boot/vfs.go) and surrounding `MustRegisterFilesystemType` calls), registers `memdev` and `ttydev` devices ([:158-162](runsc/boot/vfs.go)), and creates `/dev` nodes in `createDeviceFiles` ([:1828](runsc/boot/vfs.go)). `tmpfs`, `devtmpfs`, `proc`, `sys`, `overlay` have no host-file dependency of their own (no `//go:build linux` files in those directories; census below). `fuse` needs host `/dev/fuse` only when a FUSE server runs inside; the sentry's FUSE is in-sentry **[PARITY]**.

### Inferences
- Minimal demo rootfs: EROFS image (built on Linux with `mkfs.erofs`, or a tmpfs root populated from a tarball — gVisor already supports `overlay=memory` on top of EROFS in `runsc do --erofs`). This removes lisafs, the gofer process, directfs and `pkg/fsutil` from the runtime path, leaving `open`/`fstatfs`/`mmap` which macOS provides.
- The two filesystem-side blockers for the demo are the import-graph leaves `pkg/fdnotifier` (epoll → kqueue) and `pkg/rawfile`/`pkg/eventfd` (stub or `pipe`-based eventfd), plus `pkg/sentry/hostfd` (`pread`/`pwrite`/`preadv`/`pwritev` without `RWF_*` flags) and `fsimpl/host`'s `TCGETS` → `TIOCGETA` for a TTY stdout.
- Full host-directory access (lisafs or directfs) is a parity project: `statx`, `openat2`, `O_PATH`, `AT_EMPTY_PATH`, `renameat2`, `getdents64`, `fallocate`, `f*xattr`, `mknodat` need emulation on top of `fstatat`, `openat`, `getdirentries`/`fdopendir`, `rename`, `F_PREALLOCATE`, `fsetxattr(..., options)`.

### Gaps
- Did not measure the exact LOC of `runsc/boot/vfs.go` rootfs/tmpfs handling nor confirm whether a pure-tmpfs root (`rootfs.type` other than erofs/lisafs) is accepted by `GoferMountConf` (`NoneLower` exists but its use was not traced).
- Did not inspect `pkg/sentry/fsimpl/gofer` non-directfs lisafs client paths for additional host calls beyond `Dup3`/`Statx`.

## Key Question 3: Networking — netstack portability, host link endpoints, hostinet

### Takeaway
`pkg/tcpip` (netstack) and the `pkg/sentry/socket/netstack` provider are portable: CI already cross-builds the core netstack packages for `darwin/arm64`, `windows`, `freebsd`, `openbsd`, and `linux/mips`, and the only Linux-tagged code in `pkg/tcpip` is the host link endpoints (`fdbased`, `sharedmem`, `xdp`, `tun`, `stopfd`) and an errno translation file. The runsc side (`runsc/sandbox/network.go`, `runsc/boot/network.go`) and `hostinet` are entirely Linux (netlink, AF_PACKET, PACKET_RX_RING, veth/netns, `/proc/net`). - Did not check `pkg/tcpip/link/sharedmem` consumers (likely only the Linux "plugin" network and sandbox-to-sandbox links).
- Did not verify runtime behavior of netstack on darwin, only compilation.

## Key Question 4: Other host dependencies — seccomp, time, sync/futex, cpuid, memory, control sockets, cgroups

### Takeaway
Outside the platform, the sentry's unavoidable host contacts for a demo are: memfd + `mmap(MAP_SHARED)` + `fallocate(PUNCH_HOLE)` in `pgalloc`/`usage`, host `clock_gettime` via the Linux vDSO plus TSC in `pkg/sentry/time`, `/proc/cpuinfo`+`/proc/self/auxv` in `pkg/cpuid`, `rt_sigaction` in `pkg/sighandling` (already has a darwin stub that returns errors), and `/proc/sys/vm/mmap_min_addr`. Seccomp, cgroups, core-tagging, io_uring pin-rings, hostmm cgroup pressure, and netlink are all optional. Futexes are not a host dependency: `pkg/sync` has no futex code and `pkg/sentry/kernel` has no `SYS_FUTEX` — the in-sentry futex implementation is pure Go. urpc/control sockets are portable AF_UNIX filesystem sockets.

### Cited Findings
- **Seccomp [OPTIONAL]**: see Q1 (`DisableSeccomp` has no flag; `pkg/seccomp` 5477 LOC fails to compile on darwin). The gofer's filter is `runsc/gofer/fs/filter/filter.go` (38 LOC).
- **Time [DEMO]**: `pkg/sentry/time` samples the host clock with `vdsoClockGettime`, declared in Go and implemented in assembly that "calls clock_gettime via the Linux VDSO when available, falling back to the syscall" ([pkg/sentry/time/vdso.go:23-26](pkg/sentry/time/vdso.go), [pkg/sentry/time/vdso_amd64.tmpl.s:30-46](pkg/sentry/time/vdso_amd64.tmpl.s)), paired with `RDTSC`/`CNTVCT` sampling ([pkg/sentry/time/sampler.go:43](pkg/sentry/time/sampler.go), [:222-248](pkg/sentry/time/sampler.go)); `NewCalibratedClocks` at [pkg/sentry/time/calibrated_clock.go:277](pkg/sentry/time/calibrated_clock.go). macOS has `clock_gettime` (10.12+) and `mach_absolute_time`; the vDSO lookup must be replaced. The guest-side vDSO is a prebuilt Linux ELF from `//vdso` (`cc_binary`-style target with `cc_toolchain`, [vdso/BUILD:18-61](vdso/BUILD)) embedded as `vdsodata.Binary` ([pkg/sentry/loader/vdsodata/BUILD:11-20](pkg/sentry/loader/vdsodata/BUILD), [pkg/sentry/loader/vdso.go:182-209](pkg/sentry/loader/vdso.go)); it is OS-independent at runtime but requires a Linux-targeting C toolchain to build. **[DEMO — build-time]**
- **Sync/futex [not a dependency]**: `pkg/sync` and `pkg/syncevent` contain no `SYS_FUTEX`/`FUTEX_` references; `pkg/sync` build tags are only Go-version gates (`go1.13`, `go1.14`, `go1.21`, `go1.24`, `go1.26`, `!checklocks`). `pkg/sentry/kernel` and `pkg/sentry/kernel/futex` contain no `SYS_FUTEX`. The only `pkg/sentry/kernel` files importing `golang.org/x/sys/unix` are `fd_table.go`, `seccomp.go`, `task_syscall.go`, and they use it only for errno constants (`EBADF`, `EMFILE`, `EINVAL`, `ENOSYS`, ...).
- **cpuid [DEMO]**: `pkg/cpuid` reads `/proc/cpuinfo` for max frequency ([pkg/cpuid/native_amd64.go:209-221](pkg/cpuid/native_amd64.go); arm64 at [pkg/cpuid/native_arm64.go:62](pkg/cpuid/native_arm64.go)) and `/proc/self/auxv` for HWCAP ([pkg/cpuid/cpuid.go:333](pkg/cpuid/cpuid.go)); amd64 feature detection itself uses the `CPUID` instruction ([pkg/cpuid/native_amd64.go:109-197](pkg/cpuid/native_amd64.go)). On macOS the equivalents are `sysctl hw.*`/`machdep.cpu.*` (and for arm64, `hw.optional.*`). The failures are soft (`log.Warningf("Could not open /proc/cpuinfo")`).
- **Memory [DEMO]**: `pkg/memutil` has `memfd_linux_unsafe.go` (`SYS_MEMFD_CREATE`, tagged `linux`) plus untagged `mmap.go`/`memutil_unsafe.go`. `pkg/sentry/usage/memory.go:270` calls `memutil.CreateMemFD` (darwin compile error `undefined: memutil.CreateMemFD`). `pkg/sentry/pgalloc.NewMemoryFile(file *os.File, ...)` ([pkg/sentry/pgalloc/pgalloc.go:430](pkg/sentry/pgalloc/pgalloc.go)) mmaps the file `MAP_SHARED` ([:949](pkg/sentry/pgalloc/pgalloc.go)), decommits with `fallocate(FALLOC_FL_PUNCH_HOLE|FALLOC_FL_KEEP_SIZE)` ([:1126-1139](pkg/sentry/pgalloc/pgalloc.go)) and uses `madvise(MADV_HUGEPAGE)` ([:984](pkg/sentry/pgalloc/pgalloc.go)); it imports `pkg/sentry/hostmm`, which reads `/sys/kernel/mm/transparent_hugepage/*` ([pkg/sentry/hostmm/hostmm.go:36](pkg/sentry/hostmm/hostmm.go)), `/proc/self/mounts`, `/proc/self/cgroup` ([pkg/sentry/hostmm/cgroup.go:43-84](pkg/sentry/hostmm/cgroup.go)) and registers cgroup v1 memory-pressure eventfds (`memory.pressure_level`, `cgroup.event_control`, [pkg/sentry/hostmm/hostmm.go:70-77](pkg/sentry/hostmm/hostmm.go)) **[OPTIONAL]**. macOS equivalents: `shm_open`/`mkstemp`+`ftruncate` for the file, `mmap(MAP_SHARED)` works, punch-hole can be approximated with `F_PUNCHHOLE` fcntl (APFS) or `madvise(MADV_FREE)`/re-`mmap`.
- `pkg/sentry/platform/mmap_min_addr.go:27` reads `/proc/sys/vm/mmap_min_addr` (platform package, shared) **[DEMO, trivial]**.
- **Signals**: `pkg/sighandling` uses raw `SYS_RT_SIGACTION` ([pkg/sighandling/sighandling_linux_unsafe.go:35-72](pkg/sighandling/sighandling_linux_unsafe.go)); a darwin file already exists whose `IgnoreChildStop` and `ReplaceSignalHandler` return "not supported on Darwin" errors ([pkg/sighandling/sighandling_darwin.go:15-40](pkg/sighandling/sighandling_darwin.go)). `pkg/syserr/host_darwin.go` provides a darwin errno translation table ([pkg/syserr/host_darwin.go:15-30](pkg/syserr/host_darwin.go)). **[DEMO, partially done]**
- **eventfd [DEMO via import graph]**: `pkg/eventfd` ("represents a Linux eventfd object", [pkg/eventfd/eventfd.go:30-38](pkg/eventfd/eventfd.go)) is imported by `pkg/sentry/hostmm`, `platform/kvm/ioeventfd.go`, `pkg/sentry/state/stateipc`, `pkg/tcpip/link/sharedmem` and `pkg/unet`. A pipe-pair or kqueue `EVFILT_USER` can emulate it.
- **io_uring [OPTIONAL]**: `pkg/pinring` (`SYS_IO_URING_SETUP/REGISTER`) is imported by `pkg/sentry/platform`, `kvm`, `runsc/boot`, `runsc/sandbox`; `pkg/aio` (raw `SYS_PREAD64`/`PWRITEV2`, io_uring) is imported only by `pkg/sentry/state/stateio` (checkpoint I/O) but sits in the closure of `kernel`, `tmpfs`, `erofs`, `loader`, `mm`.
- **Core scheduling [OPTIONAL]**: `pkg/coretag` and `runsc/coretagprime` use `prctl(PR_SCHED_CORE)` ([pkg/coretag/coretag.go:38-41](pkg/coretag/coretag.go), [runsc/coretagprime/coretagprime.go:57](runsc/coretagprime/coretagprime.go)).
- **Control plane [portable]**: `pkg/control/server.CreateSocket` supports both abstract (`\x00`-prefixed) and filesystem socket paths ([pkg/control/server/server.go:133-149](pkg/control/server/server.go)); runsc deliberately uses filesystem paths (`runsc-<id>.sock`) because "abstract sockets are *not* used, because any user can connect to them" ([runsc/sandbox/sandbox.go:88-105](runsc/sandbox/sandbox.go)). - **Device proxies [OPTIONAL]**: `nvproxy`, `rdmaproxy`, `tpuproxy` are wired into `runsc/boot` ([runsc/boot/BUILD:24-76](runsc/boot/BUILD)) and `chroot.go` sysfs handling; `runsc/boot/tpuproxy.go:127-136` reads `/sys/kernel/iommu_groups`, `/sys/bus/pci`.

### Inferences
- The "kernel core" (`pkg/sentry/kernel`, `vfs`, `mm`, `loader`, `tmpfs`, `erofs`) is portable in its own code: none of these packages has a `//go:build linux` file except `kernel/{fd_table,seccomp,task_syscall}.go`, and they only need errno constants from `unix`. Their darwin failures are all transitively from ~12 leaf packages: `rawfile`, `fdnotifier`, `eventfd`, `hostfd`, `fsutil`, `fd`, `memutil`, `usage`, `hostmm`, `sighandling`, `cpuid`, `pinring`/`aio`, `seccomp`/`flipcall`/`fdchannel` (via `lisafs`), `pgalloc`, `time`.
- Estimated porting surface for the demo (non-platform): darwin variants of `fdnotifier` (~400 LOC), `rawfile`/`eventfd` stubs (~200), `hostfd` (~150), `memutil.CreateMemFD` (~30), `sighandling` (exists), `cpuid` sysctl readers (~100), `sentry/time` clock sampler (~100 + asm), `fsimpl/host` TTY ioctls (~50), `pkg/fd`/`specutils` constants (~20), plus a darwin `runsc/sandbox`+`sentrycmd` launcher that skips namespaces/chroot/seccomp/cgroups. ### Gaps
- Because `go build` stops at the first failing dependency, the scratch experiment surfaced only the *first layer* of compile errors (20 packages). `pgalloc`, `hostmm`, `sentry/time`, `cpuid`, `fsimpl/host`, `fsimpl/gofer`, `hostinet`, `usage` and the platform packages were not compiled on darwin; their errors are inferred from source inspection, not observed.
- Whether gVisor's TSC-based `CalibratedClocks` can be satisfied with `mach_absolute_time` without touching the platform's VDSO-parameter publishing was not analyzed.

## Key Question 5: Build system — Bazel/rules_go constraints, nogo, Docker-based make, and what `GOOS=darwin` builds today

### Takeaway
The in-tree sources cannot be compiled with plain `go build` (Bazel generates `go_template` instantiations, protobufs and stateify code), so meaningful darwin experiments require the synthetic `go` branch produced by `//:gopath` + `tools/go_branch.sh` (which itself needs `make build`, i.e. Docker+Bazel). The Bazel rules already carry darwin selectors (`select_system`, `select_goos`, `platforms_darwin.go`), and upstream CI cross-builds netstack for darwin. On the `go` branch under `GOOS=darwin GOARCH=arm64`, 333 of 339 packages load; 6 cannot load (via `pkg/hostsyscall` and `pkg/shim/v1/plugin`), and after stubbing `pkg/rawfile`/`pkg/fdnotifier` the first compile layer fails in 20 packages, all for Linux-only `unix.*` identifiers.

### Cited Findings
- `go.mod` declares `module gvisor.dev/gvisor`, `go 1.27.3` ([go.mod:1-3](go.mod)); local toolchain is `go1.27.3 linux/amd64`.
- In-tree `GOOS=linux go build ./pkg/sentry/kernel` fails looking for generated packages (`pkg/sentry/vfs/events_go_proto`, `pkg/metric/metric_go_proto`, `pkg/sentry/pgalloc/pgalloc_metadata_go_proto`, ...), and `GOOS=darwin go build ./pkg/abi/...` fails in dependencies with `undefined: waiterEntry`, `waiterList` (`pkg/waiter`) and `undefined: AddrRange` (`pkg/hostarch`) — template instantiations that the `go_library` wrapper generates ([tools/defs.bzl:138-176](tools/defs.bzl), `stateify = True` default, `marshal`). In-tree test directories also mix package names (e.g. `found packages stack ... and bridge (bridge_test.go) in pkg/tcpip/stack`), so `./...` is not go-tool-clean on master.

Git history includes macOS build-environment commits: `7167a339e docker: use a volume-backed bazel cache on macOS`, `8b845922d bazel: teach it about the docker socket on macOS`, `d9a6493b5 Support and document testing on macOS with CLT`, `801f45ab4 atomicbitops, cpuid: fix warnings, lack of atomics on macOS`, `82793c5e9 netstack: fix Mac build error`, `b490036d8 netstack: remove {linux,darwin}HostTranslation`.

### Inferences
- A macOS port must either (a) run Bazel natively on macOS with `--platforms` for darwin (the rules already have darwin selectors and a darwin `platforms` stub, so this is plausible), or (b) consume the `go` branch and build with the Go toolchain; (b) is simpler for iteration but the `go` branch can only be regenerated on a Linux+Docker host.
- The compile-error surface is small and concentrated in leaf packages; the structural blockers are the import-graph leaves (`rawfile`, `fdnotifier`, `hostsyscall`), not the kernel core.

### Gaps
- Bazel with a darwin `--platforms` target was not attempted (no Bazel/Docker available in this session).
- The vDSO `cc_binary` and the `//vdso` lds scripts require a Linux ELF toolchain; whether Bazel's macOS cc toolchain can be made to cross-compile it was not investigated.
- `pkg/hostsyscall` was not inspected (it blocks `platform/kvm`, `systrap`, `slimvm`, `sysmsg`, `sigframe` — platform-adjacent, out of this scope).

## Key Question 6: The demo — what `dmesg` prints, and the minimal subsystem set for a static `echo hello`

### Takeaway
`dmesg` output is synthesized entirely in-sentry (`pkg/sentry/kernel/syslog.go`): "Starting gVisor...", ten random humorous lines, and "Ready!" — it needs no host support. A static `hello` requires: platform; `Kernel.Init` (timekeeper, feature set, memory file); VFS with a root filesystem (EROFS image or tmpfs), `devtmpfs` with `memdev` (`/dev/null`, `/dev/zero`) and `ttydev`; the ELF loader with the embedded vDSO; `mm`/`pgalloc`; and stdout as an imported host FD through `fsimpl/host` (which needs `fdnotifier`/kqueue and `hostfd`).

### Cited Findings
- `syslog.Log()` builds lines with format `"<6>[%11.6f] %s\n"`, starting with `"Starting gVisor..."`, then random selections from a fixed list ("Synthesizing system calls...", "Mounting deweydecimalfs...", ..., "Rewriting the kernel in Rust...", "Politicking the oom killer..."), ending with `"Ready!"` ([pkg/sentry/kernel/syslog.go:41-116](pkg/sentry/kernel/syslog.go)). It uses only `fmt`, `math/rand`, and `pkg/sync`.
- Root filesystem options in `runsc/boot/vfs.go`: gofer (lisafs/directfs) with overlay, or EROFS via `ifd=` ([runsc/boot/vfs.go:600-640](runsc/boot/vfs.go)); `/dev` is `devtmpfs` with `memdev` and `ttydev` registered ([:117-162](runsc/boot/vfs.go)); `devpts` is auto-added when absent ([:376-378](runsc/boot/vfs.go)); OCI `linux.devices` are created by `createDeviceFiles` ([:1828-1884](runsc/boot/vfs.go)).
- Stdio: `createFDTable` imports the three stdio FDs with `host.NewFD` and detects a TTY to create a `host.TTYFileDescription` ([runsc/boot/loader.go:2498-2540](runsc/boot/loader.go)), using `ioctl(TCGETS)` ([pkg/sentry/fsimpl/host/ioctl_unsafe.go:24-35](pkg/sentry/fsimpl/host/ioctl_unsafe.go)); non-TTY pipes/files go through `hostfd.Preadv2/Pwritev2` ([pkg/sentry/hostfd/hostfd.go:89-146](pkg/sentry/hostfd/hostfd.go)) and readiness via `fdnotifier`.
- ELF loading: `pkg/sentry/loader` files importing `unix` are none except through `vdsodata`; `PrepareVDSO` copies the embedded `vdsodata.Binary` into the `MemoryFile` ([pkg/sentry/loader/vdso.go:182-209](pkg/sentry/loader/vdso.go)).
- `Kernel.Init` preconditions ([pkg/sentry/kernel/kernel.go:527-596](pkg/sentry/kernel/kernel.go)) and the `testutil.Boot` recipe ([pkg/sentry/fsimpl/testutil/kernel.go:52-104](pkg/sentry/fsimpl/testutil/kernel.go)) show the exact minimal object graph: platform → `MemoryFile` → `Timekeeper` (`NewCalibratedClocks`) → `Kernel.Init` with `FeatureSet`, `RootUserNamespace`, `RootNetworkNamespace` (loopback), `Vdso`.
- Docs: README "Requirements ... Linux 5.6+" ([README.md:66-70](README.md)); install guide "gVisor supports x86_64 and ARM64, and requires Linux 5.6+" ([g3doc/user_guide/install.md:5](g3doc/user_guide/install.md)); `g3doc/user_guide/platforms.md` has no host-OS statement beyond KVM links ([g3doc/user_guide/platforms.md:110](g3doc/user_guide/platforms.md)). The October 2026 CNCF blog lists "**gVisor-on-Mac**: Allowing Linux programs to run on macOS, with a similar experience as to how Wine allows Windows programs on macOS" as a potential non-commercial direction ([website/blog/2026-10-02-gvisor-cncf.md:91-92](website/blog/2026-10-02-gvisor-cncf.md)); the 2019 security-basics post says gVisor runs on "flavor of Linux (sorry, Windows/MacOS users)" ([website/blog/2019-11-18-security-basics.md:84](website/blog/2019-11-18-security-basics.md)). No g3doc page documents darwin/macOS support.

### Inferences — smallest launch path for a sandboxed hello world on macOS (non-platform work)
1. Build from the `go` branch with `GOOS=darwin`; add darwin files for `pkg/rawfile` (poll/readv/writev; no mmsg), `pkg/eventfd` (pipe or `EVFILT_USER`), `pkg/fdnotifier` (kqueue), `pkg/sentry/hostfd` (`pread`/`pwrite`/`preadv`/`pwritev`), `pkg/memutil.CreateMemFD` (`shm_open` or unlinked temp file), `pkg/fsutil` (only what `tmpfs`/`kernel` need), `pkg/fd` constants, `pkg/cpuid` (`sysctl`), `pkg/sentry/time` clock sampler (`clock_gettime`/`mach_absolute_time`), `pkg/sentry/hostmm` no-op, `pkg/seccomp`/`pkg/pinring`/`pkg/aio`/`pkg/coretag` no-op stubs, `pkg/flipcall` darwin ctrl (or avoid `lisafs` entirely by not linking the gofer client).
2. Launcher: a darwin `runsc/sandbox.createSandboxProcess` that `exec`s the boot binary with no `Cloneflags`/`Credential`/uid maps, `--ignore-cgroups`, `--network=none`, forced `DisableSeccomp`, no `--setup-root`/`--apply-caps`; a darwin `sentrycmd/boot.go` without `prctl`, chroot, `CallSelfAsNobody`.
3. Rootfs: EROFS image opened by runsc (goferless mode, `container.go:1748-1779`) and `mmap`ed by the sentry, optionally with `overlay=memory`; `/dev` from `devtmpfs`+`memdev`+`ttydev`.
4. Run a static binary; capture stdout through an imported host pipe FD (`fsimpl/host` non-TTY path) to avoid porting TTY ioctls first; `dmesg` works immediately because `syslog` is in-sentry.

### Gaps
- The platform itself (out of scope) remains the largest unknown; this inventory assumes a platform exists that provides `platform.Platform` and VDSO-parameter publishing.
- Whether `runsc do --erofs`/`overlay=memory` works without a gofer for *writable* roots was not verified (the `NoneLower` type and overlay filestore creation were not traced).
- `fsimpl/host` TTY support (`TCGETS` → `TIOCGETA`, termios layout) was not sized; the demo can avoid it by using a pipe for stdout.
